# Πώς συνδέεται ο ιστότοπος με το entclinic.gr

Ο ιστότοπος ζει σήμερα στο **https://dskiad.github.io/entclinic-website/**
και δημοσιεύεται αυτόματα με κάθε push στο `main`.

**Έχει επιλεγεί ο Δρόμος Β: το κύριο `entclinic.gr` στο GitHub Pages.**
Ό,τι μπορούσε να γίνει μέσα στο repository έχει γίνει (δείτε τη λίστα αμέσως
παρακάτω). Μένουν δύο πράγματα που γίνονται έξω από εδώ: η αλλαγή DNS και ένα
τσεκάρισμα στο GitHub. Οι Δρόμοι Α και Γ μένουν καταγεγραμμένοι παρακάτω ως
εναλλακτικές, αν αλλάξει η απόφαση.

## Τι έχει ήδη γίνει στο repository

- **Η κράτηση ραντεβού δείχνει στο `https://booking.entclinic.gr/book-appointment/`.**
  Και τα τρία σημεία της αρχικής (τα δύο κουμπιά και η μεταβλητή `BOOK_URL`
  της JavaScript), τα κουμπιά των τεσσάρων σελίδων περιοχής, και η σελίδα-δίχτυ.
- **`CNAME` με `entclinic.gr`.** Μόλις φύγει το push, το GitHub ορίζει μόνο του
  το custom domain — δεν χρειάζεται να γραφτεί με το χέρι στις ρυθμίσεις.
- **Όλες οι απόλυτες διευθύνσεις στο `entclinic.gr`**: canonical, προεπισκόπηση
  συνδέσμου, δομημένα δεδομένα, `sitemap.xml`, `robots.txt` και ο κωδικός QR
  των καρτών σχολίου.
- **Τέσσερις σελίδες περιοχής**: `/korydallos/`, `/nikaia/`, `/peiraias/`,
  `/peristeri/`.
- **Εργαλείο ανακατευθύνσεων** για τους υπόλοιπους παλιούς συνδέσμους:
  `docs/redirects.txt` + `tools/make-redirects.py`.

## Τι μένει, με τη σειρά που πρέπει να γίνει

1. **DNS: πρώτα το `booking`, μετά το `@`.** Ο υποτομέας πρέπει να απαντά
   *πριν* γυρίσει το κύριο domain, αλλιώς μεσολαβεί διάστημα που το κουμπί
   «Κλείστε Ραντεβού» δεν πάει πουθενά. Πίνακες παρακάτω.
2. **GitHub → Settings → Pages → Enforce HTTPS.** Το κουμπί είναι γκρίζο όσο
   εκδίδεται το πιστοποιητικό· από λίγα λεπτά έως μερικές ώρες μετά την αλλαγή
   DNS. Τσεκάρετέ το μόλις ενεργοποιηθεί.
3. **Ξανατυπώστε τις κάρτες QR** (`print/review-card.html`) — δείχνουν πλέον
   στο `entclinic.gr`.
4. **Google Search Console**: προσθέστε το `entclinic.gr` και δηλώστε το
   `sitemap.xml`.

---

Παρακάτω, οι τρεις δρόμοι αναλυτικά.

| | Δρόμος | Κίνδυνος |
|---|---|---|
| **Α** | Υποτομέας, π.χ. `new.entclinic.gr`, στο GitHub | Κανένας |
| **Β** | Το κύριο `entclinic.gr` στο GitHub | Θέλει πρώτα μεταφορά της κράτησης |
| **Γ** | Ανέβασμα των αρχείων στον δικό σας server, χωρίς αλλαγή DNS | Κανένας για DNS και email |

Αν θέλετε τη νέα σελίδα στο σκέτο `entclinic.gr` χωρίς περιπέτειες, η **Γ**
είναι ο συντομότερος ασφαλής δρόμος.

## Πριν από οτιδήποτε: δύο πράγματα που δεν πρέπει να χαλάσουν

**1. Το email.** Οι εγγραφές `MX` του entclinic.gr στέλνουν τα μηνύματα του
`lmariolis@entclinic.gr`. Η σύνδεση με το GitHub αγγίζει **μόνο** εγγραφές `A`
και `CNAME`, ποτέ `MX` ή `TXT` του email. Αν κάποιος «καθαρίσει» τις εγγραφές
του domain, το email σταματά την ίδια στιγμή.

**2. Η κράτηση ραντεβού.** Οδηγούσε στο
`https://entclinic.gr/book-appointment/`, που φιλοξενείται στον **υπάρχοντα**
server (168.119.205.208), όχι στο GitHub. Αν το `entclinic.gr` γύριζε στο
GitHub χωρίς άλλη ενέργεια, το κουμπί θα έδειχνε στον ίδιο του τον εαυτό και
δεν θα λειτουργούσε. Γι' αυτό η κράτηση μετακόμισε στον υποτομέα
`booking.entclinic.gr`, που μένει στον παλιό server με δική του εγγραφή `A`.

## Επιλογή Α — υποτομέας (χωρίς κανέναν κίνδυνο)

Π.χ. `new.entclinic.gr`. Ο υπάρχων ιστότοπος και η κράτηση ραντεβού μένουν
ακριβώς όπως είναι.

### 1. Στο DNS (panel φιλοξενίας)

Μία μόνο εγγραφή:

| Τύπος | Όνομα | Τιμή |
|---|---|---|
| CNAME | `new` | `dskiad.github.io.` |

Η τελεία στο τέλος χρειάζεται σε πολλά panel. Μην αγγίξετε τίποτε άλλο.

### 2. Στο GitHub

`github.com/dskiad/entclinic-website` → **Settings** → **Pages** →
*Custom domain* → γράψτε `new.entclinic.gr` → **Save**.

Το GitHub ελέγχει το DNS. Όταν εμφανιστεί πράσινο ✓, τσεκάρετε
**Enforce HTTPS**. Το πιστοποιητικό εκδίδεται μόνο του και θέλει από λίγα
λεπτά έως μερικές ώρες — αν το κουμπί είναι ακόμη γκρίζο, περιμένετε.

### 3. Στο repository

```
python3 tools/set-site-url.py https://new.entclinic.gr --cname
python3 tools/make-review-card.py
git add -A && git commit -m "Point the site at new.entclinic.gr" && git push
```

Το πρώτο ενημερώνει και τις 13 απόλυτες διευθύνσεις (προεπισκόπηση συνδέσμου,
δομημένα δεδομένα, sitemap, robots). Το δεύτερο ξαναφτιάχνει τις κάρτες QR,
που αλλιώς θα οδηγούν στην παλιά διεύθυνση.

## Επιλογή Β — το κύριο entclinic.gr

Η νέα σελίδα **αντικαθιστά** τον υπάρχοντα ιστότοπο.

### Η κράτηση ραντεβού — έχει λυθεί, αλλά θέλει μία εγγραφή DNS

Μόλις το `entclinic.gr` δείξει στο GitHub, το `/book-appointment/` παύει να
σερβίρεται από τον παλιό server. Η λύση που εφαρμόστηκε: η κράτηση αποκτά δικό
της υποτομέα, `booking.entclinic.gr`, που δείχνει στον **ίδιο** server με πριν.
Το repository είναι ήδη ρυθμισμένο γι' αυτό.

**Αυτή είναι η κρίσιμη εγγραφή. Χωρίς αυτήν, το κουμπί «Κλείστε Ραντεβού»
οδηγεί σε διεύθυνση που δεν απαντά.**

| Τύπος | Όνομα | Τιμή |
|---|---|---|
| A | `booking` | `168.119.205.208` |

Και στον server, το virtual host του `booking.entclinic.gr` πρέπει να
σερβίρει τη σημερινή σελίδα κράτησης στη διαδρομή `/book-appointment/`, με
δικό του πιστοποιητικό (Let's Encrypt μέσω του panel — δουλειά λεπτών για τον
τεχνικό της φιλοξενίας).

**Σειρά ενεργειών:** πρώτα η εγγραφή `booking`, επιβεβαιώνετε ότι το
`https://booking.entclinic.gr/book-appointment/` ανοίγει, **μετά** αλλάζετε το
`@`. Έτσι δεν υπάρχει στιγμή που η κράτηση δεν δουλεύει.

Αν κάποτε η κράτηση μεταφερθεί αλλού (doctoranytime, Calendly, άλλη
πλατφόρμα), μία εντολή τα ενημερώνει όλα — κουμπιά αρχικής, κουμπιά σελίδων
περιοχής και σελίδα-δίχτυ:

```
python3 tools/set-site-url.py --booking https://Η-ΝΕΑ-ΔΙΕΥΘΥΝΣΗ/
```

### 1. Στο DNS

Αντικαταστήστε την εγγραφή `A` του `@` (168.119.205.208) με τέσσερις:

| Τύπος | Όνομα | Τιμή |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |

Και για το `www`:

| Τύπος | Όνομα | Τιμή |
|---|---|---|
| CNAME | `www` | `dskiad.github.io.` |

Και η εγγραφή της κράτησης, που **μπαίνει πρώτη**:

| Τύπος | Όνομα | Τιμή |
|---|---|---|
| A | `booking` | `168.119.205.208` |

Προαιρετικά, για IPv6, τέσσερις εγγραφές `AAAA` στο `@`:
`2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`,
`2606:50c0:8003::153`.

**Τις εγγραφές MX μην τις αγγίξετε.**

### 2. Στο GitHub

Το αρχείο `CNAME` του repository γράφει ήδη `entclinic.gr`, οπότε το GitHub
ορίζει μόνο του το custom domain με το πρώτο push. Στις **Settings → Pages**
θα δείτε τη διεύθυνση συμπληρωμένη και τον έλεγχο DNS να τρέχει.

Μόλις εμφανιστεί πράσινο ✓, τσεκάρετε **Enforce HTTPS**. Το πιστοποιητικό
εκδίδεται μόνο του και θέλει από λίγα λεπτά έως μερικές ώρες — αν το κουμπί
είναι ακόμη γκρίζο, περιμένετε· δεν φταίει κάτι.

### 3. Στο repository

Έχει γίνει. Οι απόλυτες διευθύνσεις δείχνουν στο `entclinic.gr` και οι κάρτες
QR έχουν ξαναφτιαχτεί. Αν χρειαστεί να επαναληφθεί:

```
python3 tools/set-site-url.py https://entclinic.gr --cname
python3 tools/make-review-card.py
python3 tools/make-area-pages.py
```

## Το δίχτυ: τι πιάνει τους παλιούς συνδέσμους

Τρία πράγματα υπάρχουν ήδη στο repository. Όσο το DNS δεν αλλάζει, δεν κάνουν
απολύτως τίποτα. Την ημέρα που θα αλλάξει, αναλαμβάνουν.

### `book-appointment/index.html`

Πιάνει **ακριβώς** τη διεύθυνση `entclinic.gr/book-appointment/`, ώστε να μη
σπάσει κανένας παλιός σύνδεσμος: αποτελέσματα Google, καρτέλες ασθενών,
τυπωμένο υλικό, μηνύματα που έχουν ήδη σταλεί, σελιδοδείκτες.

- Αν έχει οριστεί προορισμός με `--booking`, ανακατευθύνει εκεί αμέσως.
- Αν **δεν** έχει οριστεί, δεν βγάζει σφάλμα: δείχνει σελίδα με τηλέφωνο,
  κινητό, email, διεύθυνση και ωράριο. Ο ασθενής κλείνει ραντεβού ούτως ή
  άλλως.
- Έχει φρουρά βρόχου: αν ο προορισμός είναι κατά λάθος η ίδια η σελίδα, δεν
  ανακατευθύνει ποτέ — δείχνει τα στοιχεία επικοινωνίας.

### `404.html`

Το GitHub Pages το σερβίρει για **κάθε** άγνωστη διεύθυνση. Οποιοσδήποτε άλλος
παλιός σύνδεσμος του σημερινού ιστότοπου — σελίδες WordPress, κατηγορίες,
άρθρα — αντί για το γκρίζο σφάλμα του GitHub βρίσκει σελίδα με το σήμα του
ιατρείου, έξι συνδέσμους προς τις ενότητες και το τηλέφωνο. Δείχνει και ποια
διεύθυνση ζητήθηκε, ώστε να βλέπετε ποιοι σύνδεσμοι σπάνε.

### `docs/redirects.txt` + `tools/make-redirects.py`

Το `404.html` σώζει τον επισκέπτη, αλλά δεν τον πάει εκεί που ήθελε. Για τους
συνδέσμους που αξίζουν ακριβή προορισμό — π.χ. το `/iatros/` του παλιού
WordPress στο `#doctor` της νέας σελίδας — υπάρχει λίστα και εργαλείο.

Γράψτε στο `docs/redirects.txt` μία γραμμή ανά διεύθυνση:

```
/iatros/        /#doctor
/epikoinonia/   /#contact
```

και τρέξτε:

```
python3 tools/make-redirects.py --list    # δείχνει τι θα γίνει
python3 tools/make-redirects.py           # το γράφει
```

Για κάθε γραμμή φτιάχνεται φάκελος με `index.html` που ανακατευθύνει αμέσως
(meta refresh + `location.replace`) και δηλώνει `rel=canonical` στη νέα
διεύθυνση, ώστε η Google να μεταφέρει εκεί την αξία του παλιού συνδέσμου. Αν
κοπεί η JavaScript, ο επισκέπτης βλέπει ορατό σύνδεσμο και το τηλέφωνο.

**Τι λείπει για να τρέξει:** η λίστα των διευθύνσεων του σημερινού
`entclinic.gr`. Βγαίνει από το Google Search Console (Σελίδες →
Ευρετηριασμένες) ή από το sitemap του παλιού WordPress.

## Οι σελίδες περιοχής

Τέσσερις σελίδες, μία ανά περιοχή:

| Διεύθυνση | Για ποιον |
|---|---|
| `/korydallos/` | τον Κορυδαλλό, όπου **είναι** το ιατρείο |
| `/nikaia/` | τη Νίκαια — μία στάση Μετρό |
| `/peiraias/` | τον Πειραιά — τρεις στάσεις Μετρό |
| `/peristeri/` | το Περιστέρι — οδικώς μέσω Λεωφ. Θηβών |

Ο ασθενής δεν ψάχνει «ωτορινολαρυγγολόγος». Ψάχνει «ωτορινολαρυγγολόγος
Νίκαια». Κάθε σελίδα απαντά στη δική της ερώτηση: πού είναι το ιατρείο, πώς θα
φτάσω από εκεί που είμαι, τι θα γίνει όταν έρθω, πότε πρέπει να έρθω αυθημερόν.

**Οι σελίδες λένε την αλήθεια.** Το ιατρείο είναι ένα, στον Κορυδαλλό. Οι
τρεις σελίδες δεν υπονοούν παράρτημα — ο τίτλος τους λέει «για τη Νίκαια», όχι
«στη Νίκαια», και η πρώτη ερώτηση κάθε σελίδας είναι «έχετε ιατρείο μέσα στη
Νίκαια;» με απάντηση «όχι». Σελίδες που υπονοούν ανύπαρκτες διευθύνσεις τις
τιμωρεί η Google και, χειρότερα, στέλνουν ασθενή σε λάθος μέρος.

Γεννιούνται από κώδικα, δεν γράφονται στο χέρι: τηλέφωνο, διεύθυνση και ωράριο
επαναλαμβάνονται σε τέσσερις σελίδες συν τα δομημένα δεδομένα τους. Μια αλλαγή
ωραρίου γραμμένη στο χέρι θα ξεχνιόταν κάπου — και λάθος ωράριο στη Google
είναι χειρότερο από καθόλου ωράριο.

Για αλλαγή κειμένου ή για νέα περιοχή, επεξεργαστείτε το
`tools/make-area-pages.py` (η λίστα `AREAS` στην αρχή) και τρέξτε:

```
python3 tools/make-area-pages.py
```

Ενημερώνει και το `sitemap.xml`. Η νέα περιοχή θέλει σύνδεσμο και στο υποσέλιδο
της αρχικής (`.foot-areas`), αλλιώς υπάρχει μόνο στο sitemap.

## Επιλογή Γ — χωρίς καμία αλλαγή DNS (η ασφαλέστερη)

Επιβεβαιώθηκε ότι το `entclinic.gr/book-appointment/` σερβίρεται από τον δικό
σας server. Άρα υπάρχει δρόμος όπου **δεν αγγίζουμε καθόλου το DNS** και
επομένως δεν μπορεί να χαθεί τίποτα: ανεβάζουμε τη νέα σελίδα στον server που
ήδη έχετε.

Ο ιστότοπος είναι **εξ ολοκλήρου στατικός** — HTML, CSS, γραμματοσειρές και
εικόνες. Δεν θέλει βάση δεδομένων, PHP, WordPress ούτε διαδικασία build. Είναι
51 αρχεία, 6 MB. Τρέχει σε οποιονδήποτε server, άρα και στον δικό σας.

### Βήματα

```
python3 tools/set-site-url.py https://entclinic.gr
python3 tools/make-upload-bundle.py
```

Το δεύτερο φτιάχνει το `dist/entclinic-website.zip`, με μόνο τα δημοσιεύσιμα
αρχεία — μένουν έξω τα εργαλεία, η τεκμηρίωση, οι κάρτες QR και το ιστορικό
του git. Ανεβάστε το περιεχόμενό του στον φάκελο δημοσίευσης (`public_html`,
`httpdocs`, ό,τι δείχνει το panel).

### Το μόνο σημείο προσοχής

Στον φάκελο αυτόν κάθεται σήμερα ο υπάρχων ιστότοπος. Δύο περιπτώσεις:

- **Θέλετε να μείνει και η κράτηση ραντεβού.** Τότε το WordPress πρέπει να
  εξακολουθεί να τρέχει για τη διαδρομή `/book-appointment/`, ενώ το `/` να
  σερβίρει το νέο `index.html`. Οι περισσότεροι servers σερβίρουν το
  `index.html` πριν από το `index.php`· αν όχι, ρυθμίζεται με μία γραμμή
  `DirectoryIndex index.html index.php` στο `.htaccess`. Ζητήστε το από τον
  τεχνικό της φιλοξενίας — είναι πεντάλεπτη δουλειά και **δεν** αγγίζει
  δεδομένα.
- **Θέλετε να φύγει τελείως το παλιό.** Πάρτε πρώτα πλήρες αντίγραφο
  ασφαλείας (αρχεία και βάση) και μεταφέρετε τη σελίδα κράτησης όπου θα ζει
  από δω και πέρα.

### Τι κερδίζετε

- Καμία αλλαγή DNS, άρα **μηδενικός κίνδυνος** για email και για την κράτηση.
- Ίδια διεύθυνση, ίδιο πιστοποιητικό, καμία περίοδος διάδοσης.
- Το GitHub παραμένει η πηγή αλήθειας και το ιστορικό εκδόσεων. Το
  `dskiad.github.io/entclinic-website` μένει ως αντίγραφο προεπισκόπησης —
  ή το κλείνετε από **Settings → Pages**.

### Τι χάνετε

Τη δημοσίευση με ένα push. Κάθε αλλαγή θέλει να ξανατρέξετε το bundle και να
ανεβάσετε τα αρχεία. Αυτό αυτοματοποιείται αργότερα με GitHub Actions και
SFTP, αν το θελήσετε.

## Μετά τη μεταφορά

- Το `dskiad.github.io/entclinic-website` ανακατευθύνει μόνο του στη νέα
  διεύθυνση. Οι παλιοί σύνδεσμοι δεν σπάνε.
- **Τυπώστε ξανά τις κάρτες QR.** Οι παλιές δείχνουν στην παλιά διεύθυνση·
  θα λειτουργούν μέσω ανακατεύθυνσης, αλλά μια κάρτα με ξένο domain πάνω της
  δεν είναι καλή εικόνα.
- Στο **Google Search Console** προσθέστε τη νέα διεύθυνση και δηλώστε το
  `sitemap.xml`.
- Δοκιμάστε την προεπισκόπηση συνδέσμου: στείλτε το link στον εαυτό σας σε
  Viber ή Messenger και δείτε ότι εμφανίζεται η κάρτα με το πορτραίτο.

## Προστασία από κατάληψη υποτομέα

Στον **λογαριασμό** σας (όχι στο repository): **Settings** → **Pages** →
*Add a verified domain*. Το GitHub δίνει μια εγγραφή `TXT` για να προσθέσετε
στο DNS. Αυτό εμποδίζει κάποιον τρίτο να «πιάσει» τον υποτομέα σας σε δικό του
repository αν κάποτε τον αφήσετε ελεύθερο. Δεν είναι υποχρεωτικό, είναι σωστό.

## Ασφάλεια

Τα διαπιστευτήρια του panel φιλοξενίας δεν χρειάζονται ποτέ για τη σύνδεση με
το GitHub, και δεν πρέπει να στέλνονται σε συνομιλίες, email ή μηνύματα.
Αν έχουν σταλεί, αλλάξτε τον κωδικό και ενεργοποιήστε διπλό παράγοντα.
